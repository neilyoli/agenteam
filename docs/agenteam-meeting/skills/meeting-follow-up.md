# meeting-follow-up

会议督办跟进技能。对已进入督办的任务做周期性跟进判断，结合会议最新状态给出
执行建议；只产生判断结果，不直接改写任务状态或发送消息。

## 适用场景

任务发布并完成负责人确认后，由宿主 Schedule 定时触发，判断任务是否需要跟进、
催办、升级或收尾。

## 输入说明

- `taskId` 或 `taskRef`（必填）：已发布任务的稳定标识。
- 任务当前执行状态、确认状态与最近一次会议资料（由宿主受控命令从飞书 Base 读取后传入）。

## 执行指令

1. 仅依据传入的任务状态与授权范围内的最新会议资料做判断，不自行调用写操作。
2. 逐项评估：
   - **确认状态**：待确认且超过确认时限时，建议再次提醒真实负责人。
   - **执行状态**：临近或超过建议截止日期仍未完成时，建议催办并标注风险等级。
   - **资料变化**：后续会议若更新了交付物或口径，建议据此提出修订，交由人工复核。
   - **收尾条件**：交付物与验收标准均已满足时，建议标记完成待确认。
3. 对每项建议标注依据来源与风险，不伪造进度、不臆断状态。

## 输出说明

输出结构化跟进建议：

- `followUpNeeded`（布尔）、`suggestions`（建议列表）
- 每条建议含 `type`（remind/escalate/revise/close）、`reason`、`riskLevel`、`dueDate`

## 示例

输入：`taskRef = T-2026-1101-01`，状态为待确认且已超过确认时限。
输出：

```json
{
  "followUpNeeded": true,
  "suggestions": [
    { "type": "remind", "reason": "负责人超时未确认", "riskLevel": "medium" }
  ]
}
```
