# 飞书会议搜索 API 契约与限制

## 当前能力

`agenteam.meeting` 的 `meeting_search` 使用飞书视频会议 Open API 的按会议号查询接口：

`GET /open-apis/vc/v1/meetings/list_by_no`

此接口不是企业级会议历史全量列表。调用必须提供 9 位 `meeting_no`，时间筛选使用 Unix 秒级时间戳，时间范围最多 90 天。

工具接受带时区的 ISO-8601 `startTime` / `endTime`，由插件转换为 Unix 秒。默认范围为最近 90 天。

## 不能做的事

- 不能只提供日期范围来列出企业所有会议。
- 不能把会议详情中的 `meeting_id` 当作 9 位 `meeting_no`。
- 不能传入超过 90 天的时间范围。
- 不能把 ISO-8601 字符串直接拼进飞书 API 的时间参数。

## 获取全部会议的后续方案

若业务要求“最近三天全部会议”，需要另接一个有权限边界的来源，例如：
- 飞书日历事件 API：按已授权用户或明确的日历范围列出日程，再提取会议链接/会议号；
- 企业会议数据导出/管理接口：需确认租户权限、可用范围和官方契约；
- 事件订阅 Inbox：将收到的会议事件作为已知会议索引，再通过 meeting_get 读取。

不能把按会议号查询 API 包装成全量搜索。

## 会议详情与参会人

会议详情使用 `GET /open-apis/vc/v1/meetings/{meeting_id}`，并请求参会人信息。插件从同一响应读取会议详情与参会人，不再调用未经核实的 `/participant_list` 路径。

## 验收

- 9 位会议号是必填参数。
- 时间格式校验、时区转换和 90 天上限有自动化测试。
- 分页返回 `hasMore` 和 `pageToken`。
- 会议详情映射包含参会人列表。
- 无会议号时给出明确可操作错误，不发出无效飞书请求。
